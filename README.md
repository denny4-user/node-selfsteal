# node-selfsteal

Self-steal для Xray Reality на ноде Remnawave. Ставит рядом с `remnanode` отдельный Caddy в Docker. Caddy отдаёт простой сайт с настоящим сертификатом Let's Encrypt на `127.0.0.1:9443`, а Reality отправляет туда всех, кто не прошёл проверку.

Зачем: если в SNI указан чужой сайт (`max.ru`, `poliigon.com` …), а IP принадлежит хостингу, ТСПУ видит несовпадение и со временем блокирует подсеть. При self-steal SNI — ваш домен, и он указывает на этот же IP.

## Перед запуском

1. A-запись `поддомен → IP ноды`. В Cloudflare — без проксирования (серое облако).
2. Порт 80 открыт снаружи (нужен для выпуска сертификата).
3. На ноде есть Docker с compose, `remnanode` на 443.

## Установка

```bash
curl -fsSL https://raw.githubusercontent.com/denny4-user/node-selfsteal/main/selfsteal.sh | bash -s -- cdn-se.example.com
```

Скрипт:
- проверяет, что домен указывает на эту машину, а порты 80 и 9443 свободны;
- кладёт `docker-compose.yml`, `Caddyfile` и страницу-заглушку в `/opt/selfsteal`;
- запускает контейнер `selfsteal-caddy` (`network_mode: host`; наружу открыт только 80, сайт на `127.0.0.1:9443`);
- ждёт сертификат и печатает, что вписать в панель.

`remnanode` не затрагивается. Повторный запуск с другим доменом меняет домен.

## Настройки в панели

Профиль ноды, inbound, `realitySettings`:

```json
"target": "127.0.0.1:9443",
"serverNames": ["cdn-se.example.com"],
"xver": 0
```

У того, кто подключается к ноде (хост в подписке или outbound на другой ноде): `serverName` / SNI = `cdn-se.example.com`.

Если профиль общий на несколько нод, у каждой свой поддомен и свой запуск скрипта. В `serverNames` перечисляются все поддомены, а `target` у всех одинаковый: `127.0.0.1:9443`.

## Другое

```bash
... | bash -s -- --status      # домен, контейнер, срок сертификата
... | bash -s -- --uninstall   # удалить (сначала верните target в профиле!)
```

Параметры: `--port 9443` — другой локальный порт, `--skip-dns-check` — не сверять A-запись.
